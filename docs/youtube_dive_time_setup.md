# YouTube Liveチャット連動「次に潜る時間」のセットアップ(Issue #265)

配信中、自分(配信者)がYouTube Liveのコメント欄に数値のみのコメント(例: `24`)を
打つと、`/overlay/dive-time`に表示される「次に潜る時間」を自動更新する機能。
設計の背景・アーキテクチャは`CLAUDE.md`の「チャットコメント連動『次に潜る時間』
オーバーレイ」節を参照。

## 1. Google Cloud Consoleでの準備(初回のみ)

1. [Google Cloud Console](https://console.cloud.google.com/)で新しいプロジェクトを作成する(既存プロジェクトを流用してもよい)
2. 「APIとサービス」→「ライブラリ」で**YouTube Data API v3**を検索し、有効化する
3. 「APIとサービス」→「認証情報」→「認証情報を作成」→「OAuthクライアントID」を選択する
   - アプリケーションの種類: **デスクトップアプリ**
4. 作成したクライアントIDの詳細画面から「JSONをダウンロード」し、このリポジトリのルートに`client_secret.json`という名前で配置する
   - `.gitignore`対象のため、誤ってコミットされる心配は無い

初回のみ「OAuth同意画面」の設定(テストユーザー登録等)を求められる場合がある。配信で使う自分のGoogleアカウントをテストユーザーとして登録すること。

### 公開ステータスは「本番環境」にすること(Issue #419)

OAuth同意画面の公開ステータスが**「テスト」のままだと、リフレッシュトークンが7日で失効する**(`token.json`の再作成が毎週必要になる)。「本番環境」に公開すればこの失効は無くなるため、必ず公開しておくこと。

1. 「Google Auth Platform」→「**ブランディング**」で必須項目を入力して保存する
   - **アプリ名**・**ユーザーサポートメール**・**デベロッパーの連絡先情報(メールアドレス)** の3つだけでよい
   - 「アプリのドメイン」(ホームページ / プライバシーポリシー / 利用規約)と「承認済みドメイン」は**空欄のままでよい**。Googleの審査(verification)を受ける場合にのみ必要になる項目のため
   - **ロゴはアップロードしない**こと。アップロードすると審査への提出が必要になる(画面上にもその旨の記載がある)
2. 「Google Auth Platform」→「**対象**」に戻ると「アプリを公開」ボタンが有効になるので、公開する
   - ブランディングが未入力だと「アプリの OAuth 構成が完了していません」という警告が出てボタンが押せない

公開後も、同意画面には「このアプリは確認されていません」という警告が出る(`youtube.readonly`は機密スコープのため)。個人利用の1ユーザーなら審査は不要で、再認証が必要になったときだけ「詳細」→「安全でないページに移動」から進めればよい。

なお公開しても、`client_secret.json`を配布しない限り他人がこのアプリを使うことはできない(このファイルは`.gitignore`対象でリポジトリに含まれていない)。仮に誰かが使った場合も、その人は自分のGoogleアカウントで自分の配信のチャットを読むだけで、こちらのデータにはアクセスできない。ただし**クォータはプロジェクト単位で共有される**ため、`client_secret.json`は共有しないこと。

## 2. 初回のOAuth同意

```bash
uv run python scripts/youtube_oauth_setup.py
```

ブラウザが自動的に開くので、コメントを検知したい**配信で実際に使う**Googleアカウントでログインし、読み取り専用アクセスに同意する。成功するとリポジトリルートに`token.json`が生成される(以後`main.py`実行時に自動的に読み込まれ、必要に応じて自動更新されるため、この手順は基本的に一度だけでよい)。

`token.json`が壊れた・失効した場合(Googleアカウント側でアクセスを取り消した等)は、このコマンドを再実行すればよい。

## 3. `.env`の設定

```env
YOUTUBE_CHAT_DIVE_TIME_ENABLED=true
```

`false`(既定)のままだとバックグラウンド監視自体が起動せず、`/overlay/dive-time`は常に「未設定」表示のままになる。

## 4. 配信中の使い方

配信中、自分のアカウントでYouTube Liveのチャット欄に以下のいずれかを打つ:

| 入力 | 解釈 |
|---|---|
| `24` | 分のみの指定。直近の未来の「24分」に解決する(例: 現在23:35なら翌0:24) |
| `23:45` | そのままの時刻として解釈する |
| `2345` | コロン無しでも同様に解釈する |

不正な入力(`abc`・`99`・`25:00`等)は無視され、表示は変化しない。視聴者のコメントでは絶対に更新されない(配信者本人のコメントのみを対象にする)。

`http://<WEB_HOST>:<WEB_PORT>/overlay/dive-time`をOBSのブラウザソースとして追加すると表示が更新される。反映までは平均5〜6秒程度(最悪11秒)で、内訳は以下の2段階。

| 段階 | 間隔 | 備考 |
| --- | --- | --- |
| YouTube Data APIのポーリング | **10秒**(下限、Issue #419) | クォータを消費するため下限を設けている |
| オーバーレイページのポーリング | **1秒** | ローカルの自分のサーバーへのアクセスでクォータを消費しない |

## トラブルシューティング

- 起動時ログに「YouTube連携のトークンを読み込めませんでした」と出る: `token.json`が無い、または壊れている。手順2を再実行する
- 「配信中の放送を検出しました」のログが出ない: YouTube Live側で配信を開始できているか確認する(`liveBroadcasts.list`は配信ステータスが`active`の放送のみを返す)
- 「**YouTube Data APIのデイリークォータを使い切りました**」というWARNINGが出る: 1日の上限(既定10,000 units)を使い切っている。太平洋時間の0時(JSTの16時または17時)にリセットされるまで復帰しない。Issue #419でポーリング間隔に下限(10秒)を設け、1日あたり約5時間33分もつようにしてあるため、通常の配信では出ない想定。同じ日に長時間配信を複数回行った場合などに出うる
  - 使用状況はGoogle Cloud Consoleの「APIとサービス」→「有効なAPIとサービス」→「YouTube Data API v3」→「指標」タブで確認できる(メソッド別のリクエスト数も見られる)
  - YouTube Data APIのクォータはコンソールからは増やせず、課金アカウントを紐付けても増えない。専用の審査フォーム(YouTube API Services - Audit and Quota Extension Form)での申請が必要
- 「YouTube Data APIの呼び出しに失敗しました」というWARNINGが継続する: ネットワーク不調等の可能性がある。時間を置くと自動的にリトライする(アプリ全体は止まらない)
- 「ライブチャットが終了したため、放送の再検出に戻ります」と出る: 正常な動作。配信のライブチャットが終了すると出る(次の配信を自動的に探しに戻る)
